# SpyReels Content Agent Runtime V1

## Product rule

Natural language is the primary control surface. Buttons are shortcuts to the same Agent actions. The content artifact is the source of truth. The conversation explains what happened.

The runtime follows one architecture rule:

**Agent decides what to do. Existing SpyReels systems decide how to do it.**

## Live runtime

The live Agent surfaces now use the shared creator-level runtime instead of keeping a second command brain inside the UI.

The shared tool registry covers:

- create Reel
- refine Reel
- generate hook options
- load plan idea
- remake a public Instagram, TikTok, or YouTube video
- convert a pasted script
- create a carousel
- save to My Scripts
- schedule filming
- download the current Reel
- inspect script health

Routing prefers deterministic high-confidence creator intents and uses the lightweight classifier only when the request is ambiguous. Script-required actions are guarded by the active artifact context.

## Existing workflow adapters

The Agent does not duplicate proven SpyReels workflows.

- New ideas enter the existing analyze and generation pipeline.
- Pasted scripts use the existing `studio.convertRough` workflow.
- Public social URLs use collected URL ingestion and `useLibraryRemakeChain`, then import the finished remake into Studio as the next Reel artifact.
- Refine and hook actions use the existing Studio mutations.
- Carousel repurposing opens the existing Carousel Studio with the current Reel content.
- Save uses the existing My Scripts workflow.
- Filming reminders use a dedicated filming reminder store so filming is not confused with publishing.
- Download continues to use the branded Reel document flow mounted on the finished artifact.

## Multi-step requests

Explicit creator requests are split into a bounded plan of at most five creator-level steps. The result of one step becomes context for the next.

Examples:

- remake this TikTok, save it, then turn it into a carousel
- convert this script, make it shorter, then give me hook options
- save this Reel, then remind me to film it Friday morning

If a required artifact is not ready, the runtime pauses instead of running the next step against the wrong content.

## Conversation persistence

Agent runs and tool runs are persisted separately from content artifacts.

A persisted run stores:

- request
- workspace and user scope
- status
- current artifact reference
- pending tool
- start and completion times

Each tool run stores:

- step index
- tool
- typed action payload
- status
- structured result
- error when present

On a finished Reel, the Agent can restore the latest conversation after refresh, including completed action receipts and pending clarification state. An in-flight browser action is never repeated automatically after refresh because replaying a side effect could duplicate work.

## Filming reminders

Filming reminders are intentionally separate from post scheduling. They store the filming date, filming time, timezone, setup, opening visual, on-screen text, notes, and status.

Ambiguous requests ask a follow-up rather than guessing. Replies remain inside the same `schedule_filming` action.

## Database migrations

Later SpyReels production migrations are handled as explicit one-off Render Shell migrations rather than being added to the old Drizzle journal. Content Agent tables use:

- `drizzle/0096_filming_reminders.sql`
- `drizzle/0097_content_agent_runs.sql`
- `scripts/apply-0096-0097-content-agent.mjs`

The runner is idempotent, does not modify `__drizzle_migrations`, verifies required columns and indexes, and fails closed if it encounters a partially shaped existing table.

## Release boundary

This PR remains a draft and must not be merged or deployed yet.

Before release:

1. Complete end-to-end browser QA for idea, pasted script, Instagram, TikTok, YouTube, refine, hooks, save, filming reminder, download, carousel, Recent, refresh restore, and mobile.
2. Verify the one-off database migration against the target environment before application.
3. Confirm no Agent UI claims success before the underlying workflow completes.
4. Keep the existing generic Instagram profile-preview test failure separate unless it is proven to be caused by this PR.

Known V1 limits:

- A brand-new idea is still generated by the existing page-managed asynchronous generation flow, so a single request that says create a new Reel and then immediately repurpose it cannot yet continue automatically after generation.
- The existing browser-side social Remake chain is not a durable server job. A browser refresh during the Remake itself can interrupt that chain even though Agent run history is persisted.
- Active tool cancellation and mid-flight redirect are not exposed until underlying workflows can be cancelled safely.
